## carp

Louisiana Field Conditions Explorer. Question: how have river and weather conditions changed around candidate carp-removal locations, and which need operational review today? Eight demonstration locations (SMML1 Simmesport, KRZL1 Krotz Springs, BLRL1 Butte La Rose, MCGL1 Morgan City (Atchafalaya), BTRL1 Baton Rouge, AEXL1 Alexandria, MLUL1 Monroe, BXAL1 Bogalusa); L'CARP works only in the Atchafalaya Basin and targets silver, bighead, grass and black carp. The feeds describe conditions only: no carp abundance, catch, legal access or trip safety.

Feeds: `usgs`, `nwps`, `nws`, `iem`.

### New tools

- **`site_status`**: Per-site operational review status for the carp locations: needs review flag with each reason (rule id, value, threshold, evidence ids), flood category now and at forecast peak, low water flag, and per-feed freshness (green <= 2 h, amber <= 6 h, red older; forecast stale after 36 h). Accepts asOf to recompute from data known at that time.
  - Input: { sites?: string[] (lid or name; default all eight), asOf?: RFC 3339 (knowledge time; default now) }
  - Output: rows of { site, name, basin, needsReview, reasons: [{ rule, value, threshold, evidenceIds }], categoryNow, categoryPeak, lowWater, feeds: { usgs, nwps, nws: { state, newestAt, ageHours } } }
  - Evidence: reading:<usgs site>:stage_m:<ms>:measured, forecast:<lid>:<issued ms>, alert:<id>
- **`river_readings`**: Observed stage and discharge series per site from USGS (15 min) and NWPS observed (hourly), each labelled with source and unit, plus window summary (latest, min, max, net change, 24 h mean for tidal MCGL1) and the known datum offset note (KRZL1).
  - Input: { sites?: string[], from?: RFC 3339, to?: RFC 3339, hours?: number (default 24), params?: ('stage' | 'discharge')[], source?: 'usgs' | 'nwps' | 'both' }
  - Output: rows of { site, source, param, unit, latest: { value, at }, change, min, max, mean24h?, notMeasured?: boolean, datumNote? }
  - Evidence: reading:<station>:<param>:<observed ms>:measured
- **`river_forecast`**: NWPS river forecast issuances per site, bitemporal: the issuance current at asOf (or a named issuance), its valid range, 6 hour points, peak and peak flood category, the site's NWPS thresholds (-9999 treated as missing), horizon, and provenance (nwps-live or iem-archive). Can return the previous issuance for revision comparisons.
  - Input: { sites?: string[], asOf?: RFC 3339 (knowledge time; default now), issuedAt?: RFC 3339, previous?: number (also return N earlier issuances) }
  - Output: rows of { site, issuedAt, provenance, validFrom, validTo, points: [{ at, stageFt, flowKcfs? }], peak: { at, stageFt, category }, thresholds: { action, minor, moderate, major }, stale: boolean }
  - Evidence: forecast:<lid>:<issued ms>
- **`forecast_verify`**: Score one past issuance against NWPS observed stage at its valid times: paired points, error per point, mean absolute error, max miss, and how many valid times have not happened yet.
  - Input: { sites?: string[], issuedAt?: RFC 3339, daysAgo?: number }
  - Output: rows of { site, issuedAt, pairs: [{ at, forecastFt, observedFt, errorFt }], meanAbsErrorFt, maxErrorFt, pending }
  - Evidence: forecast:<lid>:<issued ms>, reading:<lid>:stage_m:<ms>:measured
- **`review_history`**: Transitions of one site's needs review status over a window, with the time of each flip and the rule and evidence that caused it.
  - Input: { site: string, from?: RFC 3339, to?: RFC 3339 (default last 7 days) }
  - Output: { site, transitions: [{ at, from, to, rules: [{ rule, value, threshold, evidenceIds }] }] }
  - Evidence: forecast:<lid>:<issued ms>, reading:..., alert:<id>
- **`weather_forecast`**: NWS gridpoint forecast periods for a site or point (api.weather.gov), with the office updateTime used for freshness.
  - Input: { site?: string (carp location id or name), lat?: number, lon?: number, periods?: number (default 6) }
  - Output: { office, grid, updateTime, periods: [{ name, start, end, temperatureF, windSpeed, windDirection, precipProbability, shortForecast }] }
  - Evidence: forecast:nws:<office>/<grid>:<updateTime ms>
- **`source_info`**: Static facts about one feed of the active app: publisher, API URL, human page, licence and attribution text, cadence, typical latency, rate limit, coverage limits, and what the feed can and cannot tell us. Read from the app config, no network call.
  - Input: { feed: string (a feed id of the active app, e.g. usgs, nwps, crw) } or {} for all feeds
  - Output: rows of { feed, publisher, apiUrl, pageUrl, licence, attribution, cadence, latency, rateLimit, coverage, limits[] }
  - Evidence: source:<feed>
- **`evidence`**: Fetch one cited record by evidence id (wraps GraphQL `evidence(id)`): the record, its source API URL, publisher page, fetch time, ingest lag, feed state and links such as duplicateOf or the forecast issuance it belongs to.
  - Input: { id: string (C14 evidence id, e.g. reading:..., sighting:..., forecast:...) }
  - Output: { id, kind, record, sourceUrl, sourcePageUrl, fetchedAt, ingestLagSeconds, feed, links[] }
  - Evidence: the id passed in
- **`team_board`**: Read the active app's team board (GraphQL `board(id: "<app>:main")`): missions with their sites or areas and dates, and committed messages with author, recipient, thread and time. Human records, not a data feed.
  - Input: { kind?: 'missions' | 'messages' | 'all', about?: string (place, site or area name), hours?: number (default 168) }
  - Output: { missions: [{ id, title, place, bbox, start, end, assignees }], messages: [{ id, from, to, thread, at, body }] }
  - Evidence: mission:<id>, message:<id>

## lionfish

Lionfish Watch. Question: where should we prioritise lionfish surveys, given recent sightings, reef heat stress and ocean conditions? Lionfish (Pterois volitans/miles) only, in four areas: Florida Keys (fl-keys), Mexican Caribbean (mx-caribbean), Belize (belize, thin) and Colombian Caribbean (co-caribbean, thin). Sightings are not abundance; heat stress is context; no single risk percent; field conditions stay separate from priority.

Feeds: `inat`, `gbif`, `nas`, `crw`, `openmeteo`, `ndbc`, `coops`, `goes19`.

### New tools

- **`reef_heat`**: NOAA Coral Reef Watch values (CRW_SST, CRW_SSTANOMALY, CRW_DHW, CRW_BAA) at reef cells of the four areas, latest or as a daily series, with the data date and latency.
  - Input: { area?: 'fl-keys' | 'mx-caribbean' | 'belize' | 'co-caribbean', bbox?: BBox, from?: RFC 3339, to?: RFC 3339, at?: RFC 3339 }
  - Output: rows of { area, cell, lat, lon, date, sstC, anomalyC, dhwCWeeks, baa, baaLabel, latencyDays, series?: [...] }
  - Evidence: reading:crw:<cell>:<param>:<date ms>:satellite
- **`marine_forecast`**: Open-Meteo Marine hourly forecast (wave height, wave period, current velocity converted from km/h, current direction) for an area point or place, 72 hour horizon, with daily summaries and the model run time.
  - Input: { area?: string, place?: string, lat?: number, lon?: number, days?: number (max 3) }
  - Output: { point, runAt, horizonHours, hourly: [{ at, waveM, wavePeriodS, currentKmh, currentMs, currentDirDeg }], daily: [{ date, waveMaxM, waveMeanM, currentMaxKmh }] }
  - Evidence: reading:openmeteo:<lat,lon>:wave_m:<at ms>:modeled
- **`source_info`**: Static facts about one feed of the active app: publisher, API URL, human page, licence and attribution text, cadence, typical latency, rate limit, coverage limits, and what the feed can and cannot tell us. Read from the app config, no network call.
  - Input: { feed: string (a feed id of the active app, e.g. usgs, nwps, crw) } or {} for all feeds
  - Output: rows of { feed, publisher, apiUrl, pageUrl, licence, attribution, cadence, latency, rateLimit, coverage, limits[] }
  - Evidence: source:<feed>
- **`evidence`**: Fetch one cited record by evidence id (wraps GraphQL `evidence(id)`): the record, its source API URL, publisher page, fetch time, ingest lag, feed state and links such as duplicateOf or the forecast issuance it belongs to.
  - Input: { id: string (C14 evidence id, e.g. reading:..., sighting:..., forecast:...) }
  - Output: { id, kind, record, sourceUrl, sourcePageUrl, fetchedAt, ingestLagSeconds, feed, links[] }
  - Evidence: the id passed in
- **`team_board`**: Read the active app's team board (GraphQL `board(id: "<app>:main")`): missions with their sites or areas and dates, and committed messages with author, recipient, thread and time. Human records, not a data feed.
  - Input: { kind?: 'missions' | 'messages' | 'all', about?: string (place, site or area name), hours?: number (default 168) }

### New tools

- **`weather_forecast`**: NWS gridpoint forecast periods for a site or point (api.weather.gov), with the office updateTime used for freshness.
  - Input: { site?: string (carp location id or name), lat?: number, lon?: number, periods?: number (default 6) }
  - Output: { office, grid, updateTime, periods: [{ name, start, end, temperatureF, windSpeed, windDirection, precipProbability, shortForecast }] }
  - Evidence: forecast:nws:<office>/<grid>:<updateTime ms>
- **`source_info`**: Static facts about one feed of the active app: publisher, API URL, human page, licence and attribution text, cadence, typical latency, rate limit, coverage limits, and what the feed can and cannot tell us. Read from the app config, no network call.
  - Input: { feed: string (a feed id of the active app, e.g. usgs, nwps, crw) } or {} for all feeds
  - Output: rows of { feed, publisher, apiUrl, pageUrl, licence, attribution, cadence, latency, rateLimit, coverage, limits[] }
  - Evidence: source:<feed>
- **`evidence`**: Fetch one cited record by evidence id (wraps GraphQL `evidence(id)`): the record, its source API URL, publisher page, fetch time, ingest lag, feed state and links such as duplicateOf or the forecast issuance it belongs to.
  - Input: { id: string (C14 evidence id, e.g. reading:..., sighting:..., forecast:...) }
  - Output: { id, kind, record, sourceUrl, sourcePageUrl, fetchedAt, ingestLagSeconds, feed, links[] }
  - Evidence: the id passed in
- **`team_board`**: Read the active app's team board (GraphQL `board(id: "<app>:main")`): missions with their sites or areas and dates, and committed messages with author, recipient, thread and time. Human records, not a data feed.
  - Input: { kind?: 'missions' | 'messages' | 'all', about?: string (place, site or area name), hours?: number (default 168) }
  - Output: { missions: [{ id, title, place, bbox, start, end, assignees }], messages: [{ id, from, to, thread, at, body }] }
  - Evidence: mission:<id>, message:<id>
